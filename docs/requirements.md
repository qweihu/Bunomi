# Bunomi 需求文档（MVP）

## 1. 项目定位

Bunomi 面向日语初学者，把日文文本中的汉字转换为 HTML `<ruby>` / `<rt>` 振假名格式，让用户可以直接在 Agent 对话、Markdown 阅读器或后续 HTML 阅读器中读出汉字发音。

项目名和核心目标沿用“帮助用户读日语”的方向，但不把歌词作为唯一场景：歌词、学习笔记、新闻、教材和聊天内容都属于目标输入。

## 2. 用户问题

日语初学者通常能识别平假名、片假名，却无法稳定判断汉字读音、送假名和多音字。单纯让大模型猜读音会出现“读音对但包裹范围错”“送假名被纳入 ruby”“多音字选错”等问题，因此需要一个可重复执行、可校验、可替换词典引擎的本地工具。

## 3. 目标与非目标

### 3.1 MVP 目标

- 接收命令行参数、stdin 或 UTF-8 文件中的文本。
- 判断输入是否像日语；对纯汉字的中日文歧义主动拦截，不静默猜测。
- 默认使用 SudachiPy + sudachidict-core 进行上下文词法分析和读音；保留 Fugashi + UniDic-lite + PyKakasi 作为兼容回退，并支持显式选择引擎。
- 对经过人工确认的上下文短语使用带 ID、读音和理由的覆盖规则，规则命中可在 JSON 中审计。
- 默认只给汉字添加平假名振假名；送假名保持在 ruby 外部。
- 支持可选罗马音模式，供学习者或 Agent 使用。
- 输出 Markdown（默认）、最小 HTML 或 JSON。
- 输出前检查 ruby 标签闭合、原文是否被改变、是否仍有未标注汉字。
- 只有用户显式提供输出路径时才写文件；默认不创建随机文件、不覆盖已有文件。
- 支持从 Yomitan/JMdict release 获取可登记版本的词典快照，作为词典增强和审计对照；不把第三方词典归档打进默认 Python package。
- 提供项目内 `skills/bunomi/SKILL.md`，指导 Agent 在对话中呈现结果，并在用户确认路径后导出。
- 依赖独立仓库 `japanese-language-core`（Nihongo Core）：包含 reading 与 translation
  两大能力模块，共享翻译技能 `japanese-translation` 从该仓库安装，支持默认简体中文
  和多语言扩展，不与 Bunomi 应用层混在一起。

### 3.2 暂不纳入 MVP

- 自动抓取 URL、网页正文清洗和版权内容提取。
- 自动翻译不混入 Bunomi 本地代码；由 `japanese-language-core` 的 translation
  能力与共享技能 `$japanese-translation` 提供。
- 高级视觉样式、主题、响应式阅读器和点击释义。
- 账号、云端存储、数据库和在线 API。
- 完全解决人名、地名、歌词化表达等所有上下文歧义；这些场景需要可替换的高级词法/词典引擎和人工复核。

## 4. 典型用户流程

### 4.1 对话内呈现

1. 用户粘贴一段文本并要求“给日语汉字标注假名”。
2. Agent 调用 Bunomi CLI，输入通过 stdin 或临时文本参数传入。
3. CLI 返回带 `<ruby>` 的 Markdown 文本和校验状态。
4. Agent 将标注文本直接呈现在对话中；如果用户没有明确要求文件，不创建文件。

### 4.2 明确导出

1. 用户指定完整文件路径，例如 `/Users/name/Documents/japanese/lesson-01.md`。
2. Agent 将该路径传给 `--output`。
3. 目录不存在时默认停止并提示用户确认；只有用户明确允许创建目录时才增加 `--create-parent`。
4. 文件已存在时默认拒绝覆盖；用户明确确认后才使用 `--overwrite`。
5. 成功后返回规范化的绝对路径。

### 4.3 HTML 预览

MVP 允许使用 `--format html` 生成最小 HTML 文档，以便浏览器打开；视觉样式、词语点击、字号和主题作为后续需求单独设计。

## 5. 功能需求

### FR-01 输入

- 支持 `bunomi "日本語を読む"`。
- 支持 `cat input.txt | bunomi`。
- 支持 `bunomi --file input.txt`。
- 输入和导出统一使用 UTF-8。
- 保留原始换行、空行、空格、英文和符号。

### FR-02 日语检测

- 检测平假名、片假名、日文汉字和日文标点。
- `ja`：日语比例足够高，可以处理。
- `mixed`：日语和其他内容混合，处理日语片段并给出警告。
- `ambiguous`：只有汉字，没有日语信号，默认拒绝，避免把中文误标成日语。
- `non-ja`：没有足够日语信号，默认拒绝。
- `--force` 允许用户在确认语境后绕过检测。

### FR-03 振假名

- 默认输出 `<ruby>漢字<rt>かんじ</rt></ruby>`。
- 送假名应保留在 ruby 外，例如 `食べる` 应接近 `<ruby>食<rt>た</rt></ruby>べる`。
- 同一词的连续汉字可作为一个 ruby 单位，例如 `日本語`。
- 非汉字日文字符默认不标注、不删除。
- 罗马音模式使用 PyKakasi 的 Hepburn 读法，并将日文表面片段包裹为 ruby。

### FR-04 输出

- `markdown`：输出可直接粘贴到 Markdown 的文本。
- `html`：输出带 UTF-8 声明的最小 HTML 文档。
- `json`：输出语言检测、模式、标注结果、ruby 数量和警告，便于 Agent 集成。

### FR-05 质量校验

- 标签数量和闭合关系正确。
- 去除 ruby 标签后，文本与输入一致。
- 所有应处理的汉字都位于 ruby 中。
- 任一校验失败时命令以非零状态退出，不导出不可信结果。

### FR-05A 词典数据来源

- 上游默认使用 `yomidevs/jmdict-yomitan` 的最新 release。
- 默认资产包括通用 JMdict、JMnedict、KANJIDIC 和 JMdict Forms；带例句的 JMdict 按需获取。
- 每个本地快照必须记录 release tag、下载地址、获取时间、文件大小和 SHA-256。
- Yomitan 词典读音是候选信息和审计证据，不得静默覆盖 Sudachi 或人工审核规则。
- 网络不可用或资产变更时应明确报错，不使用未登记的随机词典。

### FR-06 文件权限与路径

- 未指定 `--output` 时只写 stdout。
- `--output -` 明确表示 stdout。
- 输出路径解析为绝对路径并显示给用户。
- 不自动猜测桌面、下载或项目目录。
- 默认拒绝覆盖；显式 `--overwrite` 才可覆盖。
- 默认不创建父目录；显式 `--create-parent` 才创建。
- 权限失败时返回包含目标路径和下一步动作的错误信息。

## 6. Agent Skill 需求

Skill 的职责是编排而不是重新猜读音：

- 识别用户是否要求汉字注音、平假名或罗马音。
- 对直接粘贴文本调用本地 CLI。
- 不把未提供的正文、标题、翻译或歌词补出来。
- 在对话中直接呈现 Markdown 结果。
- 只有用户指定或确认了导出路径才写文件。
- 可在用户另外要求时调用 Agent 的翻译能力，但翻译不写入核心注音脚本。
- 对 `mixed`、`ambiguous`、依赖缺失和导出权限错误如实提示。

## 7. 验收标准

- `食べると日本語` 能保留送假名并生成两个合法 ruby。
- 中日混合文本不会丢失英文。
- 中文或英文输入默认不会被静默处理。
- 无 `--output` 时不会在磁盘创建结果文件。
- 已存在目标文件不会被默认覆盖。
- `python -m unittest discover -s tests` 通过。
- 实际安装依赖后，CLI 能处理 `夢ならばどれほどよかったでしょう`。
