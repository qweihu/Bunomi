# Bunomi 需求文档（MVP）

## 1. 项目定位

Bunomi 面向日语初学者，把日文文本中的汉字转换为 HTML `<ruby>` / `<rt>` 振假名格式，让用户可以直接在 Agent 对话、Markdown 阅读器或后续 HTML 阅读器中读出汉字发音。

项目名和核心目标沿用“帮助用户读日语”的方向，但不把歌词作为唯一场景：歌词、学习笔记、新闻、教材和聊天内容都属于目标输入。

## 2. 用户问题

日语初学者通常能识别平假名、片假名，却无法稳定判断汉字读音、送假名和多音字。单纯让大模型猜读音会出现“读音对但包裹范围错”“送假名被纳入 ruby”“多音字选错”等问题，因此需要一个可重复执行、可校验、可替换词典引擎的本地工具。

## 3. 目标与非目标

### 3.1 MVP 目标

- 接收命令行参数、stdin 或 UTF-8 文件中的文本。
- 判断输入是否像日语；对纯汉字的中日文歧义主动拦截，不静默猜测。
- 由共享 `japanese-language-core` 自动选择可用的上下文读音能力；应用层不暴露引擎选择。
- 对经过人工确认的上下文短语使用带 ID、读音和理由的覆盖规则，规则由本地核心能力内部管理。
- 默认只给汉字添加平假名振假名；送假名保持在 ruby 外部。
- 支持可选罗马音模式，供学习者或 Agent 使用。
- 默认输出独立 HTML；用户明确要求时输出 Markdown。
- 输出前检查 ruby 标签闭合、原文是否被改变、是否仍有未标注汉字。
- 使用 `--file` 时在源文件同目录生成带时间戳的新结果文件，不覆盖源文件；不提供路径管理参数。
- 提供根目录 `SKILL.md`（仓库即技能），指导 Agent 在对话中呈现默认 HTML 结果。
- 依赖独立仓库 `japanese-language-core`（Nihongo Core）：包含 reading 与 translation
  两大能力模块，共享翻译技能 `japanese-translation` 从该仓库安装；目标语言由调用方
  根据用户指令和对话语境决定，不与 Bunomi 应用层混在一起。

### 3.2 暂不纳入 MVP

- 自动抓取 URL、网页正文清洗和版权内容提取。
- 自动翻译不混入 Bunomi 本地代码；由 `japanese-language-core` 的 translation
  能力与共享技能 `$japanese-translation` 提供。
- 高级视觉样式、主题、响应式阅读器和点击释义。
- 账号、云端存储、数据库和在线 API。
- 完全解决人名、地名、歌词化表达等所有上下文歧义；这些场景需要可替换的高级词法/词典引擎和人工复核。

## 4. 典型用户流程

### 4.1 对话内呈现

1. 用户粘贴一段文本并要求“给日语汉字标注假名”。
2. Agent 使用 Bunomi 的默认 HTML 结果。
3. 处理过程在内存中完成，Agent 展示 HTML 或按用户要求导出 Markdown。

### 4.2 明确导出

1. 用户通过 `--file input.txt` 提供文件。
2. Bunomi 在源文件同目录生成 `input.20260807-153012.html`。
3. 原文件保持不变，已存在的同名时间戳文件不会被覆盖。

### 4.3 HTML 预览

HTML 是默认结果；Markdown 仅作为明确请求的附加结果。视觉样式、词语点击、字号和主题不属于当前应用层职责。

## 5. 功能需求

### FR-01 输入

- 支持 `bunomi "日本語を読む"`。
- 支持 `cat input.txt | bunomi`。
- 支持 `bunomi --file input.txt`。
- 输入和导出统一使用 UTF-8。
- 保留原始换行、空行、空格、英文和符号。

### FR-02 日语检测

- 检测平假名、片假名、日文汉字和日文标点。
- 检测是基于文字脚本比例的保守启发式，不是通用语言识别器。
- `ja`：存在假名；汉字数达到 4 个时，假名至少为汉字数的四分之一。
- `mixed`：检测到日文脚本与非日文字母/数字混合；保留原文，但不承诺中日汉字
  段落切分。
- `ambiguous`：不含假名，或汉字数达到 4 个且假名少于汉字数的四分之一，
  默认拒绝。
- 用户明确确认纯汉字文本属于日语时，可用 `--assume-japanese` 继续处理；命令
  必须输出警告，Skill 只有在收到明确确认后才使用该选项。
- `non-ja`：没有足够日语脚本信号，默认拒绝。
- 汉字为中日共用字符，少量假名也不能证明其余汉字属于日语；无法确认时请用户
  提供明确的日语部分。

### FR-03 振假名

- 默认输出 `<ruby>漢字<rt>かんじ</rt></ruby>`。
- 送假名应保留在 ruby 外，例如 `食べる` 应接近 `<ruby>食<rt>た</rt></ruby>べる`。
- 同一词的连续汉字可作为一个 ruby 单位，例如 `日本語`。
- 非汉字日文字符默认不标注、不删除。
- 罗马音模式使用共享核心的 Hepburn 风格转换，并将日文表面片段包裹为 ruby。

### FR-04 输出

- `html`：默认输出带 UTF-8 声明的独立 HTML 文档。
- `markdown`：用户明确要求时，输出带 Ruby 的 Markdown 内容片段。

### FR-05 质量校验

- 标签数量和闭合关系正确。
- 去除 ruby 标签后，文本与输入一致。
- 所有应处理的汉字都位于 ruby 中。
- 任一校验失败时命令以非零状态退出，不导出不可信结果。

### FR-06 文件权限与路径

- 直接文本、位置参数或 stdin 输入只写 stdout。
- `--file` 输入在源文件同目录生成带时间戳的新 HTML 文件。
- 不自动创建目录，不接受任意输出路径，不覆盖源文件。
- 权限失败时返回包含目标路径和下一步动作的错误信息。

## 6. Agent Skill 需求

Skill 的职责是编排而不是重新猜读音：

- 识别用户是否要求汉字注音、平假名或罗马音。
- 对直接粘贴文本调用本地 CLI。
- 不把未提供的正文、标题、翻译或歌词补出来。
- 在对话中默认呈现 HTML 结果，用户明确要求时提供 Markdown。
- 不把输出路径管理交给 Skill。
- 可在用户另外要求时调用 Agent 的翻译能力，但翻译不写入核心注音脚本。
- 对 `mixed`、`ambiguous`、依赖缺失和导出权限错误如实提示。

## 7. 验收标准

- `食べると日本語` 能保留送假名并生成两个合法 ruby。
- 中日混合文本不会丢失英文。
- 中文或英文输入默认不会被静默处理。
- 直接输入时不会在磁盘创建结果文件。
- 文件输入时只生成带时间戳的新文件，不覆盖源文件。
- `python -m unittest discover -s tests` 通过。
- 实际安装依赖后，CLI 能处理 `夢の中で星を見た。`。

## 8. 后续路线

1. [持续] 扩充人名、地名、多音字、歌词表达等标准语料。
2. 通用词典、例句、活用和导出能力由 `japanese-language-core` 独立演进。
3. 其他视觉样式、词语点击、音频、URL 清洗和桌面/网页界面不属于 Bunomi 当前范围。

## 9. 与歌词类工作流的关系

歌词类工作流由专门的歌词技能负责，Bunomi 只处理普通学习文本的注音与导出。
共享引擎与翻译能力由独立核心提供，应用层各自保留产品逻辑。
